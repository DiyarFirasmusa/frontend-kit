# Translations

> **No i18n library yet** (`stack.i18n` is `none` in `.claude/wajiha-kit.json`): keep every user-visible string in one catalogue
> module grouped like future keys (`group.key`), no text in JSX, no second language or library without asking. The rules below
> then apply to that catalogue.

The project's languages, library and key shape win. Arabic + English with i18next and two-level keys is the kit's example:
read `ar.json` and `en.json` below as each locale file the project has.

- No hardcoded user-facing text in JSX, `aria-label`, `alt`, `title`,
  placeholders or toasts: `t('group.key')` from `useTranslation()`.
- Keys are exactly two levels (`group.key`), camelCase, static (no template keys).
- `ar.json` and `en.json` change together, in the same edit session. The edit
  hook runs `npm run i18n:validate` after each locale edit and reports a key
  missing from the other language.
- Global keys in the global `locales/` folder, feature keys in the feature's
  `locales/` (when the project splits bundles per feature — `project.md` says).
- Arabic is written as a native speaker would, not machine-literal; prices,
  phone numbers and codes stay Latin digits inside `dir="ltr"`.

## Keys held in data, bundles, plurals

- A key stored in data (a zod `message`, `meta.successMessage`, a map of status → key) is allowed, translated in
  exactly **one** helper (`translateKey`, named in `project.md`). Everything else uses a static `t('group.key')`.
  Prefer a `Record<Status, string>` of static `t()` calls over building keys (`status_${x}`).
- Load bundles so the first render never shows raw keys: merge every `locales/{ar,en}.json` at build time
  (`import.meta.glob(..., { eager: true })`) or load the feature bundle in the route loader. Never register a bundle
  from the component (`head()` and the first hydration render run before it).
- Once a shared component uses a key group, move the whole group to the global bundle; one key lives in one bundle.
- Plurals follow each language's CLDR categories, and the catch-all (`other`) is always written. With i18next: English
  needs `_one` and `_other`; an Arabic counted noun needs all six (`_zero` 0, `_one` 1, `_two` 2, `_few` n%100 3–10,
  `_many` n%100 11–99, `_other` the rest), and a missing one shows `_other`. Prefer "Label: {{count}}" (no plural
  forms) over six near-identical strings.
- With i18next: `count` is a number (a string returns the raw key). React text uses `interpolation.escapeValue: false`,
  so never put `t()` output into HTML. Links or bold inside a sentence use `<Trans i18nKey="group.key">`, never glued
  fragments.
- `ar.json` and `en.json` may differ midway through an edit session; the edit hook only warns, and the Stop gate
  blocks if they still differ.

## Call sites

- `const { t } = useTranslation()` with no namespace and no `keyPrefix`: the full key stays visible to search and to
  `i18n-ally`. Outside React: `i18n.t('group.key')` from the project's i18n setup module.
- Flatten deeper keys by joining the sub-group (`settings.accountTypePersonal`, not `settings.accountTypes.personal`).
  A list that was an array or numeric keys (`date.months.0`) becomes named keys (`date.monthJanuary`) or moves to code
  when it is data, not copy.
- Statuses and enums: a map of static calls, never a template key.

  ```ts
  export function orderStatusLabel(t: TFunction, status: OrderStatus): string {
    const labels: Record<OrderStatus, string> = {
      pending: t('orders.statusPending'),
      paid: t('orders.statusPaid'),
    }
    return labels[status]
  }
  ```

- Schemas carry keys, not text (`z.string().min(1, { message: 'validation.required' })`); the field component translates.
- Backend messages show only when they are in the UI language (the API client's error resolver decides); don't
  translate them by hand. Never build a sentence from translated fragments: word order differs between languages.
- Website (TanStack Start): the language is known on the server (cookie or URL) so the HTML renders with the right
  `lang`, `dir` and strings; never switch it after hydration. Dashboard: it comes from the persisted setting on load.
