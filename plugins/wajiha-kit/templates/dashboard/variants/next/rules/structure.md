# Folder structure (Next.js dashboard)

The kit's feature-first, ownership-based structure, merged with the layout of a production Next.js site (route
groups with a `loading.tsx` each, features grouped by area, shells in `layouts/`, `modals/` and `wrappers/`,
`contexts/`, `config/`, `i18n/`, `api/{client,errors}`). Folder structure only: the admin keeps its language in the
settings store, not in the URL.

```text
src/
├── app/                              thin: a page is a default export rendering one container
│   ├── layout.tsx  providers.tsx  not-found.tsx  error.tsx  global-error.tsx  robots.ts
│   ├── (auth)/login/page.tsx         layout.tsx redirects a signed-in user
│   ├── (app)/                        layout.tsx = session gate + shell, loading.tsx
│   │   ├── page.tsx                  overview
│   │   └── <resource>/page.tsx  <resource>/[<entity>Id]/page.tsx  <resource>/new/page.tsx
│   ├── (errors)/403/page.tsx         401 / 500 only when used
│   └── api/                          route handlers, only when the browser needs same-origin glue
├── proxy.ts                          only when the session leaves a cookie to check (see project.md); else guards live in layouts
├── features/<group>/<entity>/        group = a route group or a product area (sales, catalog, access…)
│   ├── index.tsx                     the main (list) page container
│   ├── components/  (dialog/)        what the main page uses
│   ├── hooks/                        use-<page>-page.ts (list page: use-list-page.ts), <entity>-actions.ts, query/, filter/, form/
│   ├── services/<entity>.service.ts  HTTP calls
│   ├── types/  validations/ (search.ts, form schemas)  utils/  data/ (static data)  locales/{ar,en}.json
│   ├── pages/<page>/                 every other page: its own index.tsx + hooks/ services/ types/ components/
│   ├── tabs/<tab>/                   a page split into tabs: the shell is index.tsx, one folder per tab
│   └── steps/<step>/                 a wizard: the shell is index.tsx, one folder per step
├── layouts/
│   ├── dashboard/                    index.tsx + header/ sidebar/ components/
│   ├── auth/                         index.tsx (+ header/ hooks/ when needed)
│   └── errors/                       the shell of (errors): composes the dashboard and auth shells (the one allowed sideways import)
├── components/
│   ├── ui/        primitives (generated by shadcn; hand-written primitives such as button, icon, status-badge live here too)
│   ├── common/                       small shared pieces with no better home: page-title, back-link, section-card, detail-row
│   ├── table/  filters/  fields/     DataTable; FilterBar; react-hook-form field wrappers
│   ├── wrappers/                     <DataWrapper>, skeletons, error and empty states
│   ├── modals/                       ConfirmDialog, FormDialog, delete modal
│   └── cards/                        cards used by 2+ features
├── api/client/  api/errors/  api/services/   privateApi, publicApi, interceptors; error resolution; app-wide calls (/me, logout, refresh)
├── contexts/                         React contexts and providers (query provider). `app/providers.tsx` composes them with `i18n/`'s provider
├── config/                           static policy: which nav item needs which permission
├── i18n/                             provider, client setup, resources, language switcher (component + hook)
├── constants/  guards/  hooks/  store/  lib/  types/  utils/  locales/  styles/  test/
└── env.ts
```

## Path map (what the shared rules and skills call things)

| A rule or skill says                          | In this variant                                |
| --------------------------------------------- | ---------------------------------------------- |
| `src/layout/`, `src/layout/app/`              | `src/layouts/`, `src/layouts/dashboard/`       |
| `nav-config`                                  | `src/config/nav.ts`                            |
| `src/services/` (token, session, `/me`)       | `src/api/services/`                            |
| `src/components/wrapper/`                     | `src/components/wrappers/`                     |
| `src/components/dialog/`                      | `src/components/modals/`                       |
| `src/api/core/` (config, envelope, interceptors) | `src/api/client/`                           |
| `src/api/error/`                              | `src/api/errors/`                              |
| i18n setup in `src/lib/`                      | `src/i18n/`                                    |
| the query provider                            | `src/contexts/`                                |
| `features/<group>/<entity>/`, `services/`, …  | the same names                                 |

## Rules that decide

- **A file lives in the deepest folder that contains every importer** (one page: that page; two sibling pages: their
  parent `pages/`; the main page: the feature root; two features: `src/`). Promote on the second use, never before.
- **The feature root is the main page**; every other page is a folder under `pages/` and owns its files.
- **Containers render, hooks think**: `index.tsx` calls one orchestrating hook; presentational components never fetch.
- **Hooks by role**: server state in `hooks/query/`, filter state in `hooks/filter/`, form state (dialog or page) in `hooks/form/`.
- **Page hook name**: `use-<page>-page.ts` (`use-list-page.ts` for the main list, `use-overview-page.ts`, `use-settings-page.ts`).
- A feature without a main page (errors, overview) keeps what its pages share at the feature root, never in `pages/components/`.
- Optional folders stay uncreated until used: no empty `header/`, `hooks/`, `401/`, `500/`.
- A `(group)` folder under `app/` holds only the framework's special files (`default.tsx` for a parallel slot, for example)
  and route folders: no logic, no components.
- No barrels (`index.ts` re-exports); kebab-case files; a page never imports a sibling page; imports go up, never sideways.
