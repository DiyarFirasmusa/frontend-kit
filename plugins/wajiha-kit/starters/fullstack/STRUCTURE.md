# دليل القالب الكامل (موقع + لوحة إدارة)

هذا قالب لمشروع واحد فيه جزءان:

1. **الموقع العام**: صفحة رئيسية، من نحن، خدماتنا، أخبار، وصفحة تواصل فيها فورم. يُرسم على السيرفر (SSR) حتى يقرأه Google، وفيه SEO وحماية كاملة.
2. **لوحة الإدارة (admin)**: صفحة دخول، ثم إطار فيه قائمة جانبية وشريط علوي، وفيه ثلاث صفحات: نظرة عامة، الموردون (جدول كامل: بحث، فلتر، صفحات، إضافة، تعديل، حذف)، والإعدادات (فورم الملف الشخصي).

الجزءان في مشروع TanStack Start واحد، بأمر تشغيل واحد، وبنظام تصميم واحد (نفس الألوان والخطوط والمسافات).
اللغة جزء من الرابط في الجزأين: `/ar/...` و `/en/...`، ولوحة الإدارة على `/ar/admin` و `/en/admin`.

كل المحتوى تجريبي لشركة وهمية ("شركة المثال" / "Example Company")، وبيانات الموردين وهمية أيضاً.

إذا كنت تعمل مع Claude: الملف `CLAUDE.md` في جذر المشروع هو النسخة المختصرة لهذا الدليل (الأوامر والقواعد وخريطة المجلدات)، والمجلد `.claude/rules/` فيه قواعد قصيرة تُحمَّل حسب الملف الذي يُفتح (الراوت، طبقة الـAPI، الترجمة، الألوان، الصلاحيات، الاختبارات).

## قبل أن تبدأ

- تحتاج **Node 24 أو أحدث** (`node -v`). الملف `.npmrc` فيه `engine-strict=true`، فالنسخة الأقدم توقف `npm install`.
- لا تحتاج أي حساب أو باكند لتشغيل المشروع على جهازك: `npm run dev` يشغّل لوحة الإدارة على **API وهمي داخل المتصفح** (MSW).

## التشغيل

```text
npm install
npm run dev              # http://localhost:5190  (الموقع)  و  http://localhost:5190/ar/admin  (الإدارة، API وهمي)
```

`npm run setup:env` (مرة واحدة) ينسخ `.env.example` إلى `.env.local`. لا تحتاجه لـ`npm run dev`، لكن `build` و`start` يقرآن منه.

**الدخول إلى لوحة الإدارة في الوضع الوهمي** (أي كلمة مرور تعمل):

| اسم المستخدم | ماذا يحدث |
| --- | --- |
| أي اسم | مدير: كل الصلاحيات |
| `viewer` | **قراءة فقط**: لا تظهر أزرار الإضافة والتعديل والحذف، والـAPI الوهمي يرد `403` على أي تغيير حتى لو لُعب بالواجهة |
| `expired` | يدخل، ثم كل طلب بعده يرد `401`: هكذا ترى مسار "انتهت الجلسة" |
| `blocked` | الدخول نفسه يرد `401`: هكذا ترى مسار "كلمة المرور خاطئة" |

الـAPI الوهمي يطبّق ما يطبّقه الباكند الحقيقي (جلسة صالحة وإلا `401`، وصلاحية وإلا `403`)، فالواجهة تُختبر أمام API يقول "لا" وليس أمام API يوافق دائماً.

أوامر أخرى:

```text
npm run dev:api          # نفس المنفذ، لكن لوحة الإدارة تكلّم الـAPI الحقيقي (VITE_ADMIN_API_MOCK من .env.local)
npm run build            # نسخة الإنتاج في .output/
npm run build:proof      # نفس build مع source maps مخفية، تُنقل فوراً من .output إلى .proof-maps/ (لا تُخدَّم ولا تُنشر؛ الفحص التالي يقرؤها من هناك)
npm run check:maps       # يفشل إن وُجد أي ملف .map في .output (الـDockerfile يشغّله بعد بنائه)
npm run check:bundle     # بعد build:proof: حجم كل صفحات الموقع تحت الميزانية وبدون أي ملف إدارة (انظر "الموقع لا يحمّل كود الإدارة")
npm start                # يشغّل نسخة الإنتاج على المنفذ 3000
npm run tokens           # يولّد ملفات الألوان من src/style/tokens (بعد أي تغيير في الألوان أو المسافات)
npm run fmt              # ينسّق الملفات (بعد توليد أو نسخ ملفات)
npm run check            # الأنواع، اللنت، حدود الاستيراد، التنسيق، الترجمة، المتغيرات، CSS، الأدوات، اختبارات الوحدة
npm run e2e:install      # مرة واحدة: متصفح Chromium للاختبارات
npm run test:e2e         # يبني المشروع ويختبره في متصفح حقيقي (المنفذ 5191، أو E2E_PORT=5401 مثلاً)
npm run check:full       # check ثم build:proof ثم check:bundle ثم test:e2e
```

## المتغيرات (ملف `.env.local`)

كل المتغيرات مشروحة في `.env.example`. الملف `.env.local` لجهازك فقط ولا يُرفع إلى git.

| المتغير | ماذا يفعل |
| --- | --- |
| `VITE_SITE_URL` | عنوان الموقع بدون `/` في الآخر. منه روابط canonical والـsitemap. مطلوب للبناء. |
| `VITE_ALLOW_INDEXING` | `true` فقط للموقع الحقيقي. غير ذلك كل الصفحات `noindex`. |
| `VITE_ADMIN_API_URL` | عنوان الـAPI الذي تكلمه لوحة الإدارة: مسار على نفس الموقع (`/api`) أو عنوان كامل (`https://api.example.com`). إذا كان على نطاق آخر يُضاف تلقائياً إلى CSP. |
| `VITE_ADMIN_API_MOCK` | `false` (الافتراضي، في الكود وفي `.env.example` وفي Docker): لوحة الإدارة تكلّم `VITE_ADMIN_API_URL`، ولا يدخل كود MSW في البناء أصلاً. `true`: API وهمي داخل المتصفح (أي دخول يعمل، والبيانات تعود لأصلها عند تحديث الصفحة). |
| `CSP_MODE` | `enforce` (الافتراضي) أو `report-only` لأول نشر. |
| `CONTACT_WEBHOOK_URL` | العنوان الذي يستقبل رسائل فورم التواصل. مطلوب على الموقع الحقيقي. |

**قاعدة الـAPI الوهمي (واحدة):** هو مطفأ ما لم يطلبه شيء صراحة. `npm run dev` يطلبه بنفسه (يشغّل Vite بوضع `mock`، انظر `vite.config.ts`)، لذلك يعمل الاستنساخ الجديد بلا أي إعداد. أما `npm run dev:api` و`build` و`start` وصورة Docker فتقرأ `VITE_ADMIN_API_MOCK` من البيئة، وقيمته الافتراضية `false`. اختبارات e2e تشغّله صراحة في سكربتها. أي بناء فيه `VITE_ALLOW_INDEXING=true` مع `VITE_ADMIN_API_MOCK=true` **يتوقف بخطأ** (الموقع الحقيقي لا يقبل أي دخول)، إلا إذا وُضع `ALLOW_MOCK_ON_REAL_SITE=1` لعرض تجريبي مقصود.

ما يبدأ بـ`VITE_` يصل للمتصفح، فلا تضع فيه سراً.

### الحدود بين الأجزاء (قاعدة لنت تفرضها، ويثبت سكربت أنها تعمل)

- `features/site` لا يستورد من `features/admin`، والعكس.
- `components` و `shared` و `style` و `config` لا تستورد من أي `features` أو `routes`.
- إذا احتاج الجزءان نفس الشيء، انقله إلى `components` (إذا كان واجهة) أو `shared` (إذا لم يكن).
- `axios` يُستورد فقط داخل `features/admin/api`، وطبقة الـAPI لا تستورد واجهة ولا راوتر. وعميل الـAPI (`api/client`) والعناوين (`api/endpoints`) لا يستوردهما إلا `api/` وملفات `<x>.service.ts`: الصفحات والـhooks والمكونات تمر على الخدمة (مثل `auth/logout.service.ts` و`settings/settings.service.ts`).
- لا يستورد `mocks/` ولا `src/test/` إلا الاختبارات (و`mocks/start-mocks.ts` عبر `import()` في الراوت). الموقع لا يستورد TanStack Query ولا MSW. `components/` لا يستورد `shared/server`. والـfeatures لا تستورد ملفات `routes/`.
- ملفات `routes/` و`router.tsx` و`start.ts` لا تستورد الإدارة استيراداً ثابتاً (ملفات الإدارة نفسها `routes/$locale_/admin*` مستثناة لأن خصائصها المقسومة تبقيها خارج الملف الرئيسي، و`check:bundle` يثبت ذلك).
- القاعدة تمنع الكتابتين: `@/features/admin/...` والمسار النسبي `../../../admin/...` بأي عمق.

`npm run lint:check` يفشل إذا كُسرت قاعدة. و`npm run check:boundaries` يكتب ملفات اختبار مؤقتة (`.lint-probe/`) فيها نحو 60 استيراداً ممنوعاً ومسموحاً ويتأكد أن الممنوع يُحجب والمسموح يمر، حتى لا تتوقف القاعدة عن العمل بصمت. هو جزء من `npm run check` ومن CI.

### الموقع لا يحمّل كود الإدارة

ملفات الراوت (`routes/$locale_/admin*`) جزء من الملف الرئيسي الذي تحمّله **كل صفحة عامة**. لذلك:

- لا تستورد كود الإدارة فيها بـ`import` ثابت. حمّله بـ`import()` داخل `beforeLoad` (هكذا يُحمَّل الحارس والنصوص والـAPI الوهمي)، أو ضعه في خصائص الراوت التي يقسمها المخطط وحده (`component`, `notFoundComponent`).
- `layout/admin-loading.tsx` و`layout/admin-head.ts` بلا أي استيراد عن قصد.
- `npm run check:bundle` (بعد `npm run build:proof`) يشغّل السيرفر المبني ويفتح **كل** صفحة عامة في `sitemap.xml` بالعربية والإنجليزية مع صفحة 404، ويقرأ خريطة المصدر (source map) لكل ملف JS تحمّله الصفحة، ويفشل إذا: ظهر أي ملف من `src/features/admin` أو من مجلدات الواجهة التي تخص الإدارة وحدها (`components/table|dialog|fields|ui`) غير الأربعة المسموحة في `scripts/bundle-sources.ts`، أو ظهرت حزمة `axios` أو TanStack Query أو MSW، أو تجاوزت صفحة ميزانيتها (الأرقام في أول `scripts/check-bundle-size.mjs`؛ الصفحة التي بلا رقم خاص تأخذ أكبر رقم). اسم الملف الناتج لا يخدع الفحص لأنه يقرأ المصادر. أي ملف يُضاف للقائمة المسموحة يُكتب سببه في نفس الـcommit. الرقم المقاس عند كتابة هذا الدليل: الصفحة الرئيسية 167 KB gzip (كانت 254 KB حين كان `AdminLoading` داخل الملف الذي يستورد axios).

### كيف يعمل رابط الإدارة

`$locale_` (بشرطة سفلية في الآخر) يعني: الرابط يبدأ باللغة (`/ar/admin`) لكن الصفحة **لا تدخل** داخل قالب الموقع (الهيدر والفوتر). لوحة الإدارة لها قالبها الخاص.

لوحة الإدارة تُرسم في المتصفح فقط (`ssr: false`): لا تحتاج Google ولا HTML من السيرفر، والجلسة في المتصفح. السيرفر يرسل لها:

- `X-Robots-Tag: noindex, nofollow` و `<meta name="robots" content="noindex, nofollow">` دائماً، حتى على الموقع الحقيقي.
- نفس هيدرز الأمان ونفس CSP الصارم للموقع.
- لا تظهر في الـsitemap، ولا تُمنع في robots.txt (المنع يخفي الـnoindex عن Google).

الروابط الخاطئة:

- `/ar/admin/غير-موجود`: رد `404` حقيقي مع `noindex`، وصفحة "غير موجودة" بلغة الرابط وفيها `<main>` ورابط للرجوع. نصها من `src/shared/locales` (مجموعة `error`) لأن نصوص الإدارة لا تُحمَّل قبل صفحة موجودة.
- `/fr/admin` أو `/xx/admin/login` (لغة غير معروفة): هذا الراوت يُرسم على السيرفر وليس في المتصفح، فيرد `404` حقيقياً مع `noindex` (وليس صفحة فارغة برد 200).

كل صفحة إدارة لها عنوان مستند خاص بها `الصفحة | لوحة الإدارة` (`head: adminHead('suppliers.title')` في ملف الراوت). بعد الانتقال بين الصفحات ينقل مُعلن الراوت التركيز إلى عنوان `<h1>` الجديد (داخل `<main id="admin-main">`) ويعلنه لقارئ الشاشة.

الدخول والخروج وانتهاء الجلسة:

- بدون جلسة: `/ar/admin/suppliers?page=2` يذهب إلى `login?redirect=...`، وبعد الدخول يعود المستخدم إلى نفس الصفحة (مسار العودة يُفحص: داخل الإدارة فقط، بدون `..`، وبدون صفحة الدخول نفسها).
- انتهاء الجلسة (رد `401` على طلب فيه الجلسة الحالية): تُمسح الجلسة ويذهب المستخدم إلى `login?redirect=<صفحته>&reason=expired`، وصفحة الدخول تقول "انتهت جلستك". `401` متأخر لطلب أُرسل قبل الخروج لا يفعل شيئاً.
- الخروج: يرسل طلب `logout` **مع التوكن** (`auth/logout.service.ts`)، ثم يمسح الجلسة والكاش ويذهب إلى صفحة الدخول بلا رسالة. إن رجع الـ`401` قبل أن تُركَّب لوحة الإدارة (إعادة تحميل كاملة لصفحة فيها `loader` يبدأ طلباً، وجلسة انتهت) فالحدث لا يضيع: `api/session-events.ts` يحفظ انتهاءً لم يسمعه أحد ويسلّمه مرة واحدة لأول مستمع، فينتهي المستخدم دائماً في صفحة الدخول مع الرسالة، لا في صفحة خطأ بلا مخرج (`e2e/ui/admin-reload.spec.ts` يفتح كل رابط إدارة هكذا). الخروج ورد `401` يمران على دالة واحدة (`layout/end-session.ts`: إلغاء الطلبات الجارية، مسح الجلسة، الانتقال، ثم مسح الكاش). الجلسة مخزنان (المستخدم والتوكن، والصلاحيات) يُكتبان معاً دائماً عبر `store/session.ts`، ولكل منهما `version` (الثابت `SESSION_STORE_VERSION` في `store/session-storage.ts`): جلسة محفوظة بإصدار آخر أو بلا إصدار (نسخ قديمة) أو بنصف واحد فقط تُمسح كلها مع توكنها القديم ويسجّل المستخدم دخوله من جديد، بلا ترحيل وبلا أي خطأ في الكونسول. بعد الخروج أو الانتهاء ينتقل التركيز إلى عنوان صفحة الدخول.
- تبديل اللغة داخل الإدارة يحتفظ بالمسار وبـ`?q=&status=&page=` وبـ`?redirect=`.

## نظام تصميم واحد للجزأين

المصدر الوحيد للألوان والمسافات والخطوط ملفات TypeScript في `src/style/tokens/`:

```text
src/style/
├── tokens/
│   ├── presets/neutral.ts   → ألوان الثيم الافتراضي (فاتح وداكن). ocean.ts ثيم ثانٍ لإثبات التبديل
│   ├── status.ts            → ألوان النجاح والتحذير والخطأ والوسوم (نفسها لكل الثيمات)
│   ├── foundation.ts        → الخطوط، المسافات بأسماء أدوار، عرض المحتوى، الزوايا، الظلال، الحركة، سلّم الخط
│   ├── generate-css.ts      → يكتب theme.css و preset.css
│   ├── contrast.test.ts     → يفحص تباين WCAG لكل ثيم فاتح وداكن (4.5:1 للنص، 3:1 لحلقة التركيز وحدود الحقول)
│   └── tokens.test.ts       → يتأكد أن الملفين المولّدين مطابقان للمصدر (إن فشل: شغّل npm run tokens)
├── theme.css  preset.css    → مولّدان: لا تعدّلهما بيدك، شغّل npm run tokens
├── styles.css               → الملف الوحيد الذي تحمّله الصفحات: القاعدة، حلقة التركيز، تقليل الحركة
└── button.css input.css select.css badge.css pagination.css actions.css → مكونات الإدارة
```

- **الموقع والإدارة يستعملان نفس الأسماء**: `bg-background`، `bg-surface`، `text-text-primary`، `text-text-muted`، `border-stroke`، `bg-primary` مع `text-primary-foreground`، `text-primary-text` للنص الملوّن.
- **الثيم الداكن** يتبع النظام بدون أي JavaScript (CSS فقط). إذا اختار الزائر ثيماً من الزر يُحفظ ويُطبَّق قبل أول رسم عبر سكربت صغير في `__root.tsx` (مع nonce، فـCSP يبقى صارماً). نفس الزر في الموقع والإدارة.
- **الخط**: العربي Cairo (محلي، بدون CDN)، والإنجليزي خط النظام، والاختيار تلقائي حسب `<html lang>`.
- **اتجاه منطقي فقط**: `ms-` `me-` `ps-` `pe-` `start-` `end-`. `npm run check:css` يفشل على `ml-` أو `left`.
- **حلقة التركيز** قاعدة واحدة بلون `--primary-highlight`، و**تقليل الحركة** قاعدة واحدة تلغي كل الحركات لمن يطلبها.
- **لون جديد للهوية**: انسخ `presets/neutral.ts`، غيّر عائلة `primary-*`، أضفه في `presets/index.ts`، ثم `npm run tokens` و `npm run test` (اختبار التباين يرفض أي لون ضعيف). غيّر `themeColor` في `site.config.ts` معه.
- **CSP الصارم** (`style-src 'self'`): مكتبة Base UI تحقن `<style>` وقت التشغيل لقائمة الاختيار، لذلك الإدارة ملفوفة بـ`<CSPProvider disableStyleElements>` والقاعدتان اللتان تحتاجهما في `select.css`. وzod مضبوط على `jitless` (`src/shared/lib/zod.ts`، استورد `z` منه) حتى لا يحاول `eval`.

## الصلاحيات

- كل الصلاحيات في `features/admin/constants/permissions.ts` بشكل `supplier:read`.
- الصفحة تُحمى في ملف الراوت: `requirePermission(locale, PERMS.supplier.read)`. بدونها يذهب المستخدم لصفحة "لا صلاحية".
- الزر يُخفى بـ`<Can permission={PERMS.supplier.write}>`، أو `useCan(...)` في الكود.
- الدور `admin` يمر من كل الفحوص. الإخفاء في الواجهة مجاملة فقط: **الباكند هو من يقرر**، والـAPI الوهمي يفعل ذلك أيضاً (`403`).
- رد `403` على طلب تغيير يظهر رسالة خطأ (toast) بنص الباكند ويبقى الحوار مفتوحاً. و`403` على قائمة يعرض "لا صلاحية" بدل زر إعادة المحاولة.
- ثلاثة أماكن تقول الشيء نفسه ويجب أن تتطابق: حارس الراوت، و`permission` في عنصر القائمة (`layout/nav-config.ts`)، والأزرار. صفحة تظهر في القائمة بلا حارس في ملف الراوت تُفتح لأي مستخدم بالرابط. اختبار `layout/nav-permissions.dom.test.ts` يشغّل شجرة الراوتات الحقيقية: لكل عنصر في القائمة ولكل نوع مستخدم يتأكد أن القائمة تعرض العنصر تماماً حين يسمح الحارس، فإن اختلف الاثنان يفشل الاختبار.

## كيف تضيف كياناً للإدارة (مثل الموردين)

مثال: "العملاء" على `/ar/admin/customers`. هذه الخطوات جُرّبت فعلاً على نسخة مؤقتة (نُفّذت بالترتيب ثم `tsc` والبناء واللنت واختبارات الصفحة الجديدة، كلها نجحت).

1. **الشكل**: أضف `Customer` و `CustomerRequest` في `features/admin/types/api.ts`.
2. **العناوين والمفاتيح**: `customers` في `api/endpoints.ts`، و `qk.customers` في `api/query-keys.ts`.
3. **الصلاحيات**: `customer: { read, write, delete }` في `constants/permissions.ts`. (مستخدم `viewer` الوهمي يأخذ كل صلاحيات `:read` تلقائياً.)
4. **الميزة**: انسخ `features/admin/suppliers/` إلى `customers/` (فيها `customers.service.ts` للطلبات، و`use-customer-queries.ts` مع `queryOptions`، و`prefetch.ts` يبدأ جلب القائمة مع تحميل الصفحة) وبدّل الكلمات في كل الملفات وأسمائها (`Supplier`←`Customer`، `suppliers`←`customers`، `SUP-`←`CUS-`). ثم ابحث يدوياً عن الكلمات التي لا يبدّلها استبدال الإنجليزية: النص العربي في `locales/ar.json` (`مورد`، `الموردين`...). ثم عدّل الحقول: `validations.ts`، `customer-columns.tsx`، `customer-form-dialog.tsx`، `locales/ar.json` و `en.json` (مجموعة `customers`، واسم المجموعة لا يتكرر في أي ملف لغة آخر). ملفات اللغة تُلتقط بمجلدها: لا تسجيل في أي مكان.
5. **الصفحة**: انسخ `src/routes/$locale_/admin/_shell/suppliers.tsx` إلى `customers.tsx` وبدّل الكلمات (فيه `validateSearch` لحالة الجدول في الرابط، و`requirePermission`، و`head: adminHead('customers.title')`، و`loader` يستورد `prefetch.ts` بـ`import()` فلا يدخل الملف الرئيسي).
6. **القائمة**: سطر في `features/admin/layout/nav-config.ts`، ومفتاح العنوان `admin.navCustomers` في `features/admin/locales/ar.json` و `en.json`. حقل `to` يُفحص مقابل الراوتات الفعلية: لا يُقبل قبل الخطوة 8.
7. **الـAPI الوهمي**: صفوف العينة في `mocks/seed.ts` (اكتب `seedCustomer(index)` مثل `seedSupplier` وابنِ القائمة بـ`Array.from`؛ اللنت يرفض `.map((row) => ({ ...row }))`)، وقائمتها في `mocks/db.ts` (النوع و`resetMockDb`)، وانسخ `mocks/suppliers.ts` إلى `customers.ts` (هو استدعاء واحد لـ`crudHandlers({...})`، لا تكتب handlers بيدك) وعدّل الحقول والرسائل ورمز العينة `SUP-` وبادئة المعرّف `sup`، وسطر `...customerHandlers` في `mocks/handlers.ts`. القائمة والإضافة والتعديل والحذف والبحث والترقيم والـ401 والـ403 كلها جاهزة في `crud.ts`.
8. **شغّل `npm run dev` (أو `npm run build`) مرة**: يتحدث `src/routeTree.gen.ts` وحده. قبل ذلك يشتكي `tsc` من ثلاثة أخطاء في ملف الراوت الجديد وفي القائمة، وهذا متوقع.
9. **الاختبارات**: انسخ `validations.test.ts` و `index.test.tsx` من الموردين (تعمل بعد تبديل الكلمات والخطوة 7؛ فيها حالات خطأ الحقل تحت الإدخال، وخطأ بلا حقل كـtoast، وأخطاء Spring)، وأضف حالة في `e2e/ui/admin.spec.ts`. اختبارات الصفحة المنسوخة تفترض 23 صفاً في عينة الـAPI الوهمي (صفحة ثالثة، و`SUP-021` تصير `CUS-021`): اجعل العينة 23 صفاً على الأقل أو غيّر هذه الأرقام. اختبار `nav-permissions` يلتقط العنصر الجديد من `ADMIN_NAV` وحده.
10. شغّل `npm run fmt` (التبديل والنسخ يتركان تنسيقاً ناقصاً)، ثم `npm run check`، ثم `npm run build:proof && npm run check:bundle`، ثم `npm run test:e2e`.

عدد الملفات: 19 ملفاً جديداً (مجلد الميزة 17 منها ملفا لغة و5 ملفات اختبار، والراوت، و`mocks/customers.ts`) وتعديل 10 ملفات موجودة (`types/api.ts`، `endpoints.ts`، `query-keys.ts`، `permissions.ts`، `nav-config.ts`، `locales/ar.json` و `en.json`، `seed.ts`، `db.ts`، `handlers.ts`)، والباقي يتولد. النسخة تحمل القائمة والإضافة والتعديل والحذف معاً؛ لعمليات أقل احذف القطع المعنية (الحذف مثلاً يمس الخدمة وملف الاستعلامات و`use-<x>-page` و`index.tsx` وأفعال الصف ومفاتيح اللغة والاختبارات) لكن أبقِ مجموعة الصلاحيات الثلاث (`read` و`write` و`delete`): `crudHandlers` واختبار القائمة يفترضانها. صفحة النظرة العامة ونوع `Overview` تعدّان الموردين فقط (`overview/` وله `prefetch.ts` خاص): كيان جديد لا يظهر فيها قبل تعديل `types/api.ts` ومعالج النظرة في الـAPI الوهمي والصفحة. كان التعديل 12 ملفاً مع فخاخ (اتحاد أنواع القائمة، تسجيل النصوص)؛ الآن النوع يُشتق من الراوتات والنصوص تُلتقط بالمجلد.

حالة الجدول (البحث، الفلتر، رقم الصفحة) في الرابط: `?q=...&status=inactive&page=2`. يمكن مشاركته وتحديثه وزر الرجوع يعمل. صفحة بعد الأخيرة (رابط مكتوب بيد، أو حذف آخر صف في آخر صفحة) تنقل المستخدم إلى آخر صفحة. الـ`loader` في ملف الراوت لا يجلب ولا ينتظر: يبدأ الطلب فقط (`prefetchQuery` بلا await) عند فتح الصفحة وعند تمرير المؤشر على الرابط، والصفحة تظهر فوراً بحالات التحميل والخطأ والفراغ الخاصة بها وتجد الطلب شغّالاً. QueryClient الإدارة واحد (`getAdminQueryClient()`): لم يوضع في `router.tsx` لأن ذلك الملف في الملف الرئيسي العام وأضاف 4.6 KB لكل صفحة، ولم يوضع في سياق الراوت لأن TanStack Start يفحص ما يعيده `beforeLoad` على أنه قابل للتسلسل.

## ربط باكند حقيقي

1. `VITE_ADMIN_API_MOCK=false` (هو الافتراضي) و `VITE_ADMIN_API_URL=` عنوان الـAPI، وشغّل بـ`npm run dev:api`.
2. اجعل الباكند يرد بنفس الأشكال في `features/admin/types/api.ts` (أو عدّل الأنواع والخدمات: التحويل مكانه `<x>.service.ts`، فلا تغيّر أنواع الواجهة لترضي الباكند). **الأخطاء**: تُقرأ ثلاثة أشكال (`api/problem.ts`): خطأ Spring الافتراضي `{ message }`، وProblem Details (RFC 9457) `{ detail }`، وقائمة التحقق `{ errors: [{ field, defaultMessage | message }] }` أو خريطة `{ errors: { code: "..." } }` (على 400 و409 و422). حقل مذكور في الخطأ يظهر تحت إدخاله (`lib/apply-field-errors.ts`، والطلب يُرسل بـ`silentError: true`)، وخطأ بلا حقل يظهر toast. `title` لا يُعرض عمداً: عناوين Problem Details عبارات إنجليزية عامة. صفحة بعد الأخيرة ترد بـ`items: []` وبالمجموع الحقيقي، وليس بآخر صفحة.
3. الدخول: `POST /auth/login` يرد `{ accessToken, user, roles, permissions }`. الطلبات بعدها ترسل `Authorization: Bearer ...`. أي رد 401 على طلب فيه الجلسة الحالية ينهي الجلسة ويعيد لصفحة الدخول مع رسالة. لا يوجد فحص لانتهاء التوكن في المتصفح ولا تجديد له: تبويب تُرك نائماً يعرض شاشات قديمة حتى أول طلب، فاجعل التوكن قصيراً وأضف تجديداً إن احتجت.
4. الجلسة محفوظة في `sessionStorage` (تنتهي بإغلاق التبويب، لكن أي سكربت على نفس النطاق يقرؤها). للأمان الأعلى اجعل الباكند يضع التوكن في كوكي `HttpOnly` واحذف `accessToken` من `store/auth-store.ts`؛ عندها أضف `withCredentials` ورمز CSRF أو `SameSite=Strict` (الـCSRF الموجود في `start.ts` يغطي server functions فقط وليس `/api`).
5. nginx: في `deploy/nginx/*.conf` مثال معلّق لتحديد معدل الدخول (`/api/auth/login`) وللتمرير إلى الباكند. الإقفال بعد محاولات فاشلة مكانه الباكند.
6. `public/mockServiceWorker.js` لا يدخل نسخة الإنتاج وحده إذا كان `VITE_ADMIN_API_MOCK` غير `true` (خطّاف في `vite.config.ts` يحذفه مع نسخه المضغوطة، وسطر في `Dockerfile` يكرر ذلك). `npm run check:bundle` يتأكد في بناء بلا الـAPI الوهمي: لا ملف worker في `.output/public`، و`/mockServiceWorker.js` يرد 404، ولا MSW في أي ملف JS. ولوحة الإدارة تلغي تسجيل أي worker وهمي قديم عند الفتح بدون الـAPI الوهمي.

الاختبارات تفشل على أي خطأ في الكونسول وعلى أي مخالفة CSP، وتقرأ النصوص من ملفات الترجمة. أخطاء `4xx` من الـAPI التي يستفزها الاختبار عمداً مسموحة.

## ملاحظات

- الـToaster (رسائل "تم الحفظ") مكتوب داخل المشروع وليس مكتبة: مكتبات الـtoast المعروفة تضيف `<style>` وقت التشغيل، وCSP الصارم يمنعه. نفس رسالة الخطأ لا تظهر مرتين (إعادة المحاولة التلقائية لا تكدّس رسائل). الـToaster خارج الحوار المفتوح، فقارئ الشاشة لا يعلن رسالة تظهر خلف حوار مفتوح؛ الرسالة مرئية فقط.
- `public/mockServiceWorker.js` من حزمة msw ويبقى في المجلد للتطوير، لكن البناء بـ`VITE_ADMIN_API_MOCK=true` وحده ينسخه إلى `.output`.
- oxlint و oxfmt يتجاهلان المشروع إذا كان مجلده داخل مجلد مستبعد في `.gitignore` لمستودع أب. داخل مستودعك الخاص يعملان عادي.
- زر الحساب في الشريط العلوي: اسم المستخدم المرئي هو بداية اسمه الصوتي (WCAG 2.5.3).
